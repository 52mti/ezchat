# WeChat App 自动化开发说明

本文档用于后续使用 Codex 继续开发 `apps/wechat` 自动化流程。说明以当前代码实现为准，重点写清楚目标、模块边界、运行闭环、异常处理和配置项含义。

## 1. 总体目标

WeChat 自动化的目标是：在微信聊天列表中发现未读消息，进入对应聊天，读取对方最后一句话，请求 AI 生成回复，通过机械臂点击输入法语音入口并播放 TTS 完成输入，发送后回到聊天列表继续下一轮。

当前流程只处理文本回复闭环，不处理图片、语音原消息、红包、小程序卡片等复杂消息类型。

## 2. 关键模块

- `apps/wechat/app.py`：微信自动化主流程，负责串联查找未读、进入聊天、请求 AI、输入、发送、返回、状态上报。
- `apps/wechat/steps.py`：微信页面级动作库，负责截图、弹窗处理、模板匹配、OCR、点击输入框、点击麦克风、发送、返回。
- `apps/wechat/config.py`：微信默认配置，合并运行默认值、OCR 默认值、人设默认值。
- `apps/wechat/ocr_config.py`：`dialogue` 和 `list` 两种 OCR 模式配置。
- `workers/device_worker.py`：设备线程主循环，按 `poll_interval` 调用 app 的 `run_once()`。
- `services/message_processor.py`：AI 请求、会话记忆、待发送消息 outbox 记录。
- `apps/photo_capture.py`：机械臂截图封装。运行截图默认不落盘，只有开启 `save_captures` 或错误截图才保存。
- `ui/main_window.py`：App 配置界面、运行状态、日志格式化、模板管理。

## 3. 坐标和截图约定

所有模板匹配、OCR bounds、点击坐标统一使用竖屏归一化坐标，范围为 `0.0` 到 `1.0`。

每次需要识别页面时都使用机械臂“复位后截图”，即调用机械臂截图接口时使用 `pre_move=True`。这样能保证机械臂先离开屏幕区域，再进行截图，减少遮挡和视角偏差。

当前运行截图默认不保存到 `photo/captures`，避免长期运行占用磁盘。错误时仍会保存到 `photo/errors`，用于排查失败现场。

## 4. 配置项含义

- `poll_interval`：每轮主循环结束后等待多少秒再执行下一轮。默认 `1` 秒。位置在 `workers/device_worker.py`。
- `step_timeout`：单个等待型步骤最多等待多少秒，例如等待麦克风按钮、等待发送按钮出现或消失。默认 `10` 秒。
- `keep_awake_interval_seconds`：无实际操作超过多少秒后执行防熄屏点击。默认 `200` 秒，`0` 表示关闭。
- `match_threshold`：模板匹配阈值，默认 `0.85`。
- `ocr.det_db_thresh` / `ocr.rec_thresh`：OCR 检测和识别阈值。
- `persona`：当前设备当前 App 的人设配置，会覆盖全局默认人设。

前端配置中“运行设置”只放运行相关配置；“OCR设置”默认隐藏，点击后显示；“模板管理”目前只保留“添加弹窗”。

## 5. 主流程

### 5.1 主循环入口

`DeviceWorker.run()` 会循环执行：

1. 检查暂停、停止和授权状态。
2. 调用 `WechatApp.run_once()`。
3. 上报一次 `tick` 状态。
4. 如果熔断打开，则暂停当前 worker。
5. 等待 `poll_interval` 秒进入下一轮。

### 5.2 微信单轮处理

`WechatApp.run_once()` 当前闭环如下：

1. 如果超过 `keep_awake_interval_seconds` 未发生实际操作，执行防熄屏流程。
2. 上报 `popup_check`，进入未读查找。
3. 调用 `find_unread_target()` 确认聊天列表并执行 `list` OCR。
4. 找到 `unread_count >= 1` 的目标，过滤系统通知类目标。
5. 使用目标 `bounds` 中心点点击进入聊天。
6. 调用 `read_message()` 确认聊天界面并执行 `dialogue` OCR。
7. 取 `sender1` 的最后一句消息，上报运行日志 `dialogue_ocr_last_message`。
8. 启动 AI 请求后台线程。
9. 主线程立即调用 `focus_input_box()` 定位并点击输入框。
10. 等待 AI 返回，上报运行日志 `ai_reply_text`。
11. 如果 AI 标记跳过，则返回列表并结束本轮。
12. 调用 `play_voice_reply()` 定位麦克风、点击、播放 TTS，并等待 3 秒。
13. 调用 `send_reply()` 检测发送按钮并点击发送。
14. 发送成功后记录 outbox 和会话记忆。
15. 调用 `go_back()` 返回聊天列表。
16. 记录本轮平均用时并标记成功。

## 6. 弹窗处理

任何需要重新截图的步骤都会先检查弹窗模板。弹窗模板来自当前设备当前 App 的 `buttons` 模板目录，命名模式为 `popup_*.jpg`。

弹窗命中后，点击位置为模板框右上区域：

```text
x = popup_x + popup_w * 0.9
y = popup_y + popup_h * 0.1
```

关闭弹窗后立即重新截图，最多连续处理 3 次弹窗，然后继续当前业务步骤。

模板管理当前只保留“添加弹窗”：从当前机械臂复位后截图，用户手动框选弹窗区域，保存为新的弹窗模板。

## 7. 聊天列表确认和未读扫描

`find_unread_target()` 会先调用 `_ensure_list_screen()` 保证处于聊天列表：

1. 截图并处理弹窗。
2. 匹配聊天列表模板。
3. 如果匹配成功，直接进入 `list` OCR。
4. 如果匹配到聊天窗口，调用 `go_back()` 返回列表后重新确认。
5. 如果是未知界面，先点一次返回，再重新确认列表。
6. 仍无法确认列表时返回 `None`，本轮不报错，等待下一轮。

列表 OCR 使用 `list` 模式，从结果中读取：

- `name`：聊天对象名称，用于会话记忆。
- `content`：列表当前展示内容，当前阶段不参与额外判断。
- `unread_count`：未读数量，要求 `>= 1`。
- `bounds`：列表项位置，用于计算点击中心点。

系统通知、微信团队、服务通知等会被过滤，避免误回系统消息。

## 8. 聊天界面读取

进入聊天后，`read_message()` 会：

1. 截图并处理弹窗。
2. 匹配聊天窗口模板。
3. 使用 `dialogue` OCR 模式识别聊天内容区域。
4. 从 `dialogues` 中提取 `sender1` 的最后一句非空消息。
5. 返回 `contact`、`content`、`unread_count` 等字段。

如果聊天窗口模板匹配失败，会抛出 `StepUnavailable`，进入错误处理。

## 9. AI 请求和输入优化

当前实现已经做了并行优化：读到对方消息后，AI 请求会在后台线程启动；主线程同时去定位并点击输入框。这样 AI 网络等待和输入框定位可以重叠，减少整轮耗时。

输入框点击规则：

```text
x = center_x - 0.5
y = center_y - 0.02
```

AI 返回后再继续定位麦克风、点击麦克风、播放 TTS。

## 10. TTS 和发送

`play_voice_reply()` 负责：

1. 循环截图并匹配麦克风按钮。
2. 匹配成功后点击麦克风。
3. 调用机械臂文字转语音接口播放 AI 回复。
4. 播放完成后固定等待 3 秒，再进入发送按钮检测。

`send_reply()` 负责：

1. 循环截图并匹配发送按钮。
2. 首次匹配到发送按钮时点击一次。
3. 点击后继续检测，直到发送按钮消失。
4. 如果超过 `step_timeout` 仍未出现或未消失，则抛出异常。

## 11. 返回聊天列表

`go_back()` 会先截图确认当前是否已经在聊天列表。如果已经在列表，直接返回。

如果不在列表，则匹配返回按钮模板；匹配成功时连续点击两次。匹配不到返回按钮时，兜底点击左上角 `0.08, 0.06` 两次。

## 12. 防熄屏流程

防熄屏按“无实际操作时间”触发。实际操作包括进入聊天点击、点击输入框、点击麦克风、发送、返回、防熄屏点击等；截图和 OCR 不算实际操作。

触发后流程如下：

1. 确认当前能回到聊天列表。
2. 对列表页执行 `list` OCR。
3. 从 OCR 的 `bottom_nav` 中找到“微信”或“消息”。
4. 点击该底部导航坐标一次。
5. 更新 `last_activity_at`，重新开始闲置计时。

当前不再执行“点击发现再回微信”的双跳转。

## 13. 状态和日志

每个关键步骤都会通过 `set_runtime_step()` 上报状态，前端显示当前正在做什么。

常见状态包括：

- `capture_screen`：复位后截图。
- `confirm_chat_list`：确认聊天列表。
- `list_ocr_scan`：列表 OCR 扫描。
- `enter_chat`：进入聊天。
- `confirm_chat_window`：确认聊天界面。
- `dialogue_ocr_read`：对话 OCR 读取。
- `request_ai`：请求 AI 回复。
- `input_box_locate`：定位输入框。
- `input_box_click`：点击输入框。
- `microphone_locate`：定位麦克风按钮。
- `tts_playback`：播放 TTS 回复。
- `send_button_check`：检测发送按钮。
- `return_to_list`：返回聊天列表。
- `keep_awake_due`：执行防熄屏跳转。

运行日志会额外输出：

- `dialogue_ocr_last_message`：OCR 读到的对方最后一句话。
- `ai_reply_text`：AI 生成的回复文本。
- `keep_awake_failed`：防熄屏失败原因。

## 14. 失败和恢复

失败分两类：

1. 未找到未读目标或无法确认列表：本轮直接结束，不算错误，等待下一轮。
2. 进入聊天后的关键步骤失败：抛出异常，进入 `BaseApp.on_error()`。

`on_error()` 会：

1. 增加 `error_count`。
2. 记录 `last_error`。
3. 保存错误截图到 `photo/errors`。
4. 尝试调用机械臂 `reset_device(wait=True)` 恢复。
5. 连续失败达到 `circuit_breaker_threshold` 后打开熔断。

熔断打开后，`DeviceWorker` 会暂停当前设备，避免无限错误循环。

## 15. 后续开发注意事项

- 新增动作时，优先放到 `apps/wechat/steps.py`，让 `WechatApp.run_once()` 只负责流程编排。
- 任何会点击手机屏幕的成功动作，都应在 `WechatApp` 中刷新 `last_activity_at`，否则防熄屏计时会不准确。
- 新增截图识别步骤时，应使用 `capture_after_popups()`，不要绕过弹窗处理。
- 新增长期运行截图保存需求时，必须通过配置显式开启，默认不要保存每张运行截图。
- 新增模板类型时，注意模板路径必须按当前设备当前 App 隔离，避免影响其他设备或 App。
- 修改 OCR 输出结构时，同步更新 `find_unread_target()`、`read_message()` 和对应测试。
- 修改 AI 请求链路时，保留“AI 请求并行 + 输入框提前点击”的优化，避免回到串行等待。
- 修改发送链路时，必须保留发送按钮“点击后等待消失”的确认逻辑。
