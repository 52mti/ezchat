# 心遇自动化流程说明

本文档描述当前 `apps/xinyu` 的真实自动化行为，并补充整个程序的异常处理链路。它不是微信流程的简单复用，而是针对心遇列表页、未读红点、好感度、空闲防熄屏和积分读取做过专门适配。

## 1. 目标

核心目标是：
- 在聊天列表中找到需要回复的未读会话。
- 优先选择 `favorability` 更高的目标。
- 根据列表内容决定是否直接回复。
- 必要时进入聊天详情，读取对方最后一条消息再请求 AI。
- 完成输入、TTS、发送、返回。
- 没有消息时保持设备活跃，并在每个空闲周期首次读取一次“我的积分”。

当前关键规则：
- 心遇未读红点在左侧，不使用微信右侧未读数字逻辑。
- 列表右侧数字优先视为 `favorability`。
- `list` OCR 的顶部筛选项和底部导航项进入 `bottom_nav`，不混入 `message_list`。
- `points` OCR 用于“我的积分”读取。
- UI 余额栏显示 `我的积分 / 10` 的整数部分。

## 2. 代码入口

- `apps/xinyu/app.py`：单轮流程编排。
- `apps/xinyu/steps.py`：弹窗、页面确认、OCR、点击、发送、返回、积分读取。
- `apps/xinyu/config.py`：默认运行配置。
- `apps/xinyu/ocr_config.py`：`dialogue`、`list`、`points` 三种 OCR 模式。
- `vision/ocr_rules.py`：OCR 结构化规则。
- `ui/main_window.py`：主程序 UI 和余额列。
- `workers/device_worker.py`：设备轮询、暂停、恢复、停止、许可证检查、熔断联动。
- `apps/base.py`：通用错误计数、熔断、恢复、错误截图。
- `apps/cancellation.py`：用户停止/取消检测。
- `services/message_processor.py`：消息准备、记忆、出箱记录。
- `runtime/greetings/pingtai.txt`：列表内容为“你好”时的兜底回复来源。

### 2.1 全局运行链路

心遇单台设备的实际运行链路是：
- `DeviceWorker` 先做授权检查，再根据暂停、停止和熔断状态决定是否调度。
- `DeviceWorker` 每轮调用一次 `XinyuApp.run_once()`，结束后再上报一次 `tick`。
- 当 `status.is_circuit_open` 为真时，worker 会发送 `circuit open` 事件并执行 `pause()`。
- `pause()`、`resume()`、`stop()` 只影响 worker 调度，不改心遇业务流程本身。
- UI 通过 worker 事件和 app 状态回调刷新运行状态、余额、平均回复时长和异常标记。

### 2.2 回复供应器

`reply_provider` 的默认实现来自 `services/message_processor.py`，它不是“重复消息保护”开关，而是本轮回复文本的供应器。
- `prepare_reply()` 会先计算消息指纹，再查 outbox 里是否已有 pending 回复。
- 如果存在 `pending_send`，它会直接复用那条 pending 回复文本。
- 如果没有 pending 记录，它会走会话记忆、AI 请求和 outbox 写入。
- `sent_callback` 在发送成功后把这轮消息写回 outbox，标记为已发送。
- `ReplyAction(skip=True)` 只表示本轮跳过，不代表系统把同一条消息判成异常。

## 4. 全局异常模型

程序异常分四层：

### 4.1 用户取消 / 停止

`apps/cancellation.py` 的 `OperationCancelled` 表示用户停止或线程被要求退出。
- 来自 `raise_if_cancelled()`、`cancellable_sleep()`。
- 不计入 `BaseApp.error_count`。
- 不打开熔断。
- 只是让当前步骤尽快退出。

### 4.2 通用可恢复异常

`StepUnavailable`、OCR 失败、按钮找不到、发送按钮不消失、TTS 重试失败等，都属于这类。
- 由 `BaseApp.on_error()` 统一处理。
- 会增加 `error_count`。
- 会保存错误截图到 `photo/errors`。
- 会尝试 `recover()`，当前默认是 `robot.reset_device(wait=True)`。
- 连续错误达到 `circuit_breaker_threshold` 后打开熔断。
- 恢复失败次数达到 `recover_failure_limit` 后也会打开熔断。
- 成功完成回复、跳过本轮后返回列表、或被确认为空目标的正常轮次会调用 `mark_success()`，清理 `last_error`、`error_count` 和熔断标记。

### 4.3 心遇特例异常

心遇自己在 `run_once()` 中单独处理两类：
- `NoPhoneScreenError`
- `BlackScreenError`

这两类不会进入 `BaseApp.on_error()`。
- 会设置心遇专属等待状态。
- 会把 `last_error` 写入状态。
- 不会直接触发通用熔断计数。
- 当前实现是等待态，不是立即终止流程。
- worker 会继续轮询，UI 会把它们展示为 `abnormal`。

### 4.4 许可证异常

`workers/device_worker.py` 会先做许可证检查。
- 过期、校验失败、卡密无效时，worker 直接 `pause()`。
- 运行期 license 失败通常会进入暂停态并输出错误日志，不会自动变成 `license_error`。
- UI 的 `license_error` 主要用于“卡密绑定”对话框里校验失败的直接反馈。
- 这是外层调度异常，不属于心遇业务步骤。

## 5. 页面纠偏

单轮开始先确认当前页面：
- 在聊天列表：继续。
- 在聊天界面：点返回按钮，回聊天列表。
- 在我的界面：点消息按钮，回聊天列表。
- 在未知界面：只能通过返回按钮模板纠偏，不使用默认坐标。
- 命中黑屏模板或像素黑屏：触发黑屏等待态。
- 命中无手机模板：触发无手机等待态。

## 6. 弹窗

每次重新截图都先处理弹窗，但聊天界面是例外：
- 先匹配 `screen_聊天界面.jpg`，如果确认当前截图已经在聊天界面，则只跳过弹窗模板检测。
- 跳过弹窗检测不代表中断聊天流程，当前截图仍继续交给输入框、麦克风、发送按钮、返回等正常聊天步骤使用。
- 全屏匹配弹窗模板。
- 丢弃 `x > 0.9` 的结果。
- 点击模板右上区域关闭。
- 最多处理 2 次。
- 点击失败后默认弹窗不存在，继续正常流程。

弹窗处理优先级高于页面判断、OCR 和按钮点击。

## 7. 未回复入口

在聊天列表中先做 `list` OCR，再检查 `bottom_nav` 中的 `未回复`：
- 找到后，用 bounds 周围像素判断是否有红色。
- 有红色：不点。
- 无红色：点击一次，再重新截图和 OCR。
- 没识别到 `未回复`：不占位，不强点。

红色检测以像素规则为准，条件放宽以适配实际截图色差。

## 8. list OCR

`list` 模式输出重点是：
- `message_list`
- `bottom_nav`

`message_list` 字段：
- `name`：用户名字，允许纯数字名字。
- `favorability`：右侧数字，视为好感度。
- `unread_count`：左侧红点推断，默认红点存在记为 `1`。
- `content`：列表最新内容。
- `bounds`：该行点击区域。

选择规则：
- 只选 `unread_count >= 1` 的行。
- 优先 `favorability` 更高的行。
- `favorability` 相同时，优先更靠上的行。
- 顶部筛选项和底部导航项不进入 `message_list`。

## 9. 列表内容直回

选中目标后先看 `content`：
- 清洗后内容非空且长度小于 10 个中文汉字：直接作为本轮输入。
- `content == "你好"`：优先从 `runtime/greetings/pingtai.txt` 取回复。
- `content` 为空、过长或不可靠：进入聊天详情后用 `dialogue` OCR。

即便直回，也仍然先进入聊天界面并确认 `screen_聊天界面.jpg`。

## 10. dialogue OCR

进入聊天详情后：
- 只读聊天区域。
- 从 `dialogues` 中取 `sender1` 最后一条非空消息作为 AI 输入。
- 联系人名字优先用列表页选中的 `name`。
- 没读到 `sender1` 时抛出可恢复异常。
- 心遇强制关闭 `basic_filter.enable_center_y_region_filter`，不再因为 `above_dialogue_region` / `below_dialogue_region` 丢弃对话内容。

## 11. 输入、TTS、发送、返回

进入聊天界面并确认后，先处理新招呼：
- 匹配 `btn_新招呼按钮.jpg`。
- 命中后点击 `(match_center_x + 0.2, match_center_y)`，发送新招呼。
- 发送后匹配 `btn_返回按钮_2.jpg` 并点击，返回聊天列表。
- 新招呼分支成功后，本轮不再执行列表内容直回、`dialogue` OCR、AI、TTS 和普通发送流程。
- 没有匹配到新招呼按钮时，继续下面的正常回复流程。

回复文本确定后：
- 匹配 `btn_输入框.jpg`。
- 点击 `match_center_x - 0.5, match_center_y`。
- 匹配并点击 `btn_麦克风按钮.jpg`。
- 调用 TTS 播放回复文本。
- 播放后固定等待 3 秒。

TTS 失败时：
- 重新点麦克风。
- 重新播放。
- 重试次数由配置控制，超过后抛异常。

发送流程：
- 匹配 `btn_发送按钮.jpg`。
- 只要还存在，就继续点击。
- 点击后重新截图确认按钮是否消失。

返回流程：
- 先确认发送按钮是否还在，存在则补点。
- 若已在聊天列表，直接结束。
- 否则匹配返回按钮模板。
- 如果这是发送完成后的回列表步骤，首次命中时连续点击两次。
- 其他返回场景每次匹配只点击一次；如果还没回到列表，就重新截图、重新匹配、再点击一次。
- 重新截图确认回到聊天列表。
- 不使用默认返回坐标。

## 12. 空闲、防熄屏、积分

没有消息时进入空闲维护：
- `find_unread_target()` 返回空，状态显示“暂无消息，进入防熄屏等待”。
- OCR 返回“暂无消息”等空目标，也进入空闲维护。
- worker 在 `empty_list_target` 状态下使用 `idle_poll_interval_seconds`，默认 5 秒轮询一次。
- 防熄屏通过 `list` OCR 的 `bottom_nav` 找 `消息`，且要求 `y >= 0.5`。

积分读取规则：
- 每个空闲周期首次进入防熄屏等待时，只读一次积分。
- 同一轮空闲期间不重复读取。
- 一旦遇到真实消息并进入正常回复流程，空闲周期标记重置。
- 下一次再次进入无消息空闲时，再读一次积分。

积分读取步骤：
- 确认在聊天列表。
- 点击 `btn_我的按钮.jpg`。
- 确认 `screen_我的界面.jpg`。
- 用 `points` OCR 读取“我的积分”附近的数值。
- 点击 `btn_消息按钮.jpg` 回到聊天列表。
- 上报 `xinyu_balance`。

余额显示规则：
- `points` 是 OCR 读到的“我的积分”原始值，例如 `1013.25`。
- UI “余额”显示 `points / 10` 后的整数部分。
- 例如 `1013.25` 显示 `101`，`1288` 显示 `128`。

## 13. points OCR

`points` 模式用于“我的积分”读取：
- 关键词：`我的积分` / `积分`。
- 优先在关键词同组文本中找数字。
- 如果“我的积分”和数字被拆成两行，则在附近找独立数字块。
- 返回 `points`、`balance`、`raw_text`、`bounds`。

联动程序 `jixiebijiaobenfuzhu` 已支持显示：
- `消息列表（list）`
- `聊天内容（dialogue）`
- `积分模式（points）`

## 14. 心遇专属异常

### 14.1 无手机

当命中 `screen_无手机界面.jpg` 时：
- 设置运行状态为无手机等待态。
- 记录错误信息。
- 当前实现不打开熔断。
- 由 worker 继续轮询，等待用户把手机放回去。

### 14.2 黑屏

当命中 `screen_黑屏异常.jpg` 或像素黑屏时：
- 设置运行状态为黑屏等待态。
- 记录错误信息。
- 当前实现不打开通用熔断。
- 由 worker 继续轮询，等待用户亮屏。

### 14.3 业务步骤失败

进入聊天后如果出现以下问题，通常会抛 `StepUnavailable` 或普通异常，交给 `BaseApp.on_error()`：
- 输入框找不到。
- 麦克风找不到。
- 发送按钮找不到或长时间不消失。
- 聊天详情 OCR 没有读到 `sender1`。
- TTS 播放失败且重试结束。
- 返回按钮找不到或返回后仍未回到列表。

这类异常会计数、保存错误截图、尝试恢复；达到阈值后熔断。

## 15. 重复消息

当前不再启用重复消息保护：
- 同一条消息重复出现时仍正常请求 AI 并回复。
- 不因重复消息暂停设备。
- `message_processor` 里保留的 `pending_send` 只是未发送完成时的续用，不是重复消息熔断。

## 16. 黑屏熔断与通用熔断

区分两种熔断：

### 16.1 心遇特例等待态

无手机 / 黑屏由心遇自己拦截，当前实现是等待态，不走通用熔断计数。

### 16.2 通用熔断

`BaseApp.on_error()` 会在下面情况打开熔断：
- 错误累计达到 `circuit_breaker_threshold`。
- 恢复失败次数达到 `recover_failure_limit`。

当 worker 看到 `status.is_circuit_open` 为真时：
- 发送 `circuit open` 事件。
- 调用 `pause()`。
- UI 显示 `已熔断`。
- 如果之后手工恢复，`resume()` 会先清掉 `is_circuit_open` 和 `error_count`，再继续轮询。

## 17. 单轮顺序

`XinyuApp.run_once()` 当前顺序：
1. 如果当前已熔断则直接返回；黑屏/无手机是 `run_once()` 内部单独拦截的等待态，不依赖 worker 熔断。
2. 检查弹窗。
3. 确认聊天列表并做 `list` OCR。
4. 检查 `未回复` 红色状态，必要时切换并重新 OCR。
5. 从 `message_list` 选未读目标。
6. 无目标则进入空闲维护，必要时首次读积分。
7. 目标是“暂无消息”也进入空闲维护。
8. 真实目标则重置空闲周期标记。
9. 判断列表内容是否可直回。
10. 点击目标进入聊天界面并确认。
11. 优先检查新招呼按钮；命中则发送新招呼并用 `btn_返回按钮_2.jpg` 返回列表，本轮结束。
12. 没有新招呼时，必要时做 `dialogue` OCR。
13. 请求 AI 或取招呼语。
14. 点击输入框偏移位置。
15. 点麦克风并播 TTS。
16. 点击发送直到消失。
17. 记录发送结果。
18. 发送后返回列表时，首次返回可双击；其他返回场景按单击重试。
19. 确认回到聊天列表并标记成功。

- `popup_check`
- `confirm_xinyu_list`
- `unread_button_check`

- `points_check_due`
- `points_open_my`

- `xinyu_balance`

- `new_greeting_return`

- `microphone_click`
- `tts_playback`
- `send_button_click`
- `return_to_list`
- `no_phone_waiting`

UI 侧常见状态：
- `running`
- `paused`
- `stopping`
- `stopped`
- `circuit_open`
- `license_error`
- `abnormal`

其中 `abnormal` 是把 `black_screen_waiting` / `no_phone_waiting` 聚合后的展示状态，`license_error` 只对应手工绑卡失败。

当 UI 行已经处于 `stopping` 或 `stopped` 时，后续迟到的 `status` 事件不会再把它覆盖回 `running`。
