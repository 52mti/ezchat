# 心遇见 App 自动化流程说明

本文档用于后续继续开发 `apps/xinyu` 自动化流程。说明以微信自动化流程为总体参考，但针对心遇见的页面结构、未读红点位置、好感度字段、列表内容优先回复策略做专门约定。

## 1. 总体目标

心遇见自动化的目标是：在消息列表中发现需要回复的会话，优先选择 `list` OCR 结果里 `favorability` 较高的联系人作为本轮目标，根据列表内容决定是否直接请求 AI，必要时进入聊天界面读取对方最后一句话，再通过机械臂点击输入框、麦克风、发送按钮完成语音输入和发送，最后稳定返回聊天列表。

当前重点不是通用聊天 App 逻辑，而是适配心遇见列表页：

- 未读红点在头像左侧或头像区域左上侧，不在右侧。
- 右侧数字不是未读数，优先解释为 `favorability` 好感度。
- 顶部筛选项包括 `全部消息` / `全部信息` / `未回复` / `在线` / `距离`，这些归入 `bottom_nav` 结构用于导航和排除，不作为消息列表行。
- 当列表 `content` 足够短时，可以直接作为本轮对话内容，不必进入聊天详情 OCR。

## 2. 关键模块

- `apps/xinyu/app.py`：心遇见单轮流程编排入口，后续应负责串联弹窗处理、页面确认、目标选择、AI 请求、输入、发送和返回。
- `apps/xinyu/steps.py`：页面级动作库，负责截图、弹窗处理、模板匹配、OCR、点击输入框、点击麦克风、发送、返回。
- `apps/xinyu/config.py`：心遇见默认配置，包含 OCR、模板路径、轮询、超时和人设默认值。
- `apps/xinyu/ocr_config.py`：心遇见 `dialogue` 和 `list` OCR 模式配置。`list` 模式应保持左侧未读红点和右侧好感度分离。
- `vision/ocr_rules.py`：OCR 结果结构化规则，当前承载 `message_list`、`bottom_nav`、`favorability`、`unread_count` 等字段解析。
- `runtime/greetings/pingtai.txt`：当列表内容是“你好”时，从该文件抽取一条平台招呼语作为回复内容。
- `workers/device_worker.py`：设备运行主循环，按 `poll_interval` 调用当前 App 的 `run_once()`。

## 3. 模板和截图约定

所有模板匹配、OCR bounds、点击坐标统一使用竖屏归一化坐标，范围为 `0.0` 到 `1.0`。

心遇见流程依赖以下模板：

- `screens/screen_聊天列表.jpg`：判断当前是否在聊天列表。
- `screens/screen_聊天界面.jpg`：判断当前是否在聊天详情。
- `buttons/btn_返回按钮.jpg`：聊天详情返回按钮模板之一。
- `buttons/btn_返回按钮_2.jpg`：聊天详情返回按钮模板之二。
- `buttons/btn_未读消息按钮.jpg`：列表页未读入口或未读状态检测位置。
- `buttons/btn_输入框.jpg`：聊天详情输入框区域。
- `buttons/btn_麦克风按钮.jpg`：语音输入麦克风按钮。
- `buttons/btn_发送按钮.jpg`：发送按钮。
- `buttons/popup_*.jpg`：弹窗模板，优先处理。

截图默认使用机械臂复位后的截图，即调用截图接口时使用 `pre_move=True`。任何页面判断、弹窗处理、按钮匹配和 OCR 前都应基于复位后截图，减少机械臂遮挡和角度偏差。

## 4. 弹窗处理优先级

每次进入业务步骤前先处理弹窗。弹窗处理流程如下：

1. 截图。
2. 在当前 App 的 `buttons` 模板目录中匹配 `popup_*.jpg`。
3. 命中弹窗后点击模板右上区域关闭。
4. 关闭后重新截图，再次检查弹窗。
5. 最多连续处理 2-3 次，仍有弹窗则抛出可恢复异常或结束本轮。

弹窗处理必须先于界面判断、OCR 和按钮点击，否则可能把弹窗内容误识别为列表消息或聊天内容。

## 5. 页面确认和纠偏

单轮开始后先确认当前界面：

1. 处理弹窗。
2. 匹配 `screens/screen_聊天列表.jpg`。
3. 如果已在聊天列表，进入列表处理。
4. 如果匹配到 `screens/screen_聊天界面.jpg`，说明停留在聊天详情，需要在当前截图上匹配 `buttons/btn_返回按钮.jpg` 和 `buttons/btn_返回按钮_2.jpg`，点击返回到聊天列表。
5. 返回后重新截图并再次匹配聊天列表。
6. 如果既不是聊天列表也不是聊天界面，可尝试点击一次返回，再重新确认。
7. 仍无法确认时，本轮结束，不进入 OCR 和发送流程。

这里的返回只用于纠偏，不应直接触发回复逻辑。

## 6. 未读入口状态检查

确认在聊天列表后，优先匹配 `buttons/btn_未读消息按钮.jpg`。

匹配到该位置后需要检查该区域是否有红色：

- 如果没有红色，点击该位置一次，用于切换到未读消息或刷新未读入口。
- 如果有红色，不点击，继续进入列表 OCR。

红色检测应基于模板返回区域附近的截图像素。心遇见未读红点位于左侧头像区域，不能沿用微信右侧未读数逻辑。

## 7. 列表 OCR 和目标选择

对整个界面执行 `list` 模式 OCR，不只截局部右侧区域。结果重点读取 `message_list`：

- `name`：用户名字，用于聊天记忆和联系人身份。
- `favorability`：好感度，心遇见列表右侧数字应进入该字段。
- `unread_count`：未读数量，心遇见由左侧红点判断，通常红点存在时记为 `1`。
- `content`：列表上显示的最新对话内容。
- `bounds`：列表行位置，用于点击进入聊天。

目标选择规则：

1. 只考虑 `unread_count >= 1` 的行。
2. 优先选择 `favorability` 较大的行。
3. 如果多个目标 `favorability` 相同或为空，选择列表中更靠上的未读行。
4. 系统入口、顶部筛选项、底部导航项不得进入 `message_list`。

心遇见 OCR 规则必须保持以下语义：

- 右侧 `44`、`67` 等数字是好感度，不是未读数。
- 左侧红点表示有未读，未读数量默认记为 `1`。
- 顶部 `全部消息` / `全部信息` / `未回复` / `在线` / `距离` 进入 `bottom_nav`，不参与目标选择。

## 8. 列表内容直回策略

选中目标后，根据列表字段 `content` 决定是否进入聊天详情读取：

1. 如果 `content` 非空且长度小于 10 个中文汉字，直接把 `content` 当作本轮对话内容发给 AI。
2. 如果 `content` 是“你好”，不直接请求通用 AI，从 `runtime/greetings/pingtai.txt` 抽取一条内容作为回复。
3. 如果 `content` 为空、过长，或疑似不是对方真实消息，则进入聊天界面后用 `dialogue` 模式读取。

长度判断以清洗后的文本为准，去掉空格、标点和 OCR 可能带出的装饰字符后再判断。

## 9. 进入聊天和必要 OCR

调用机械臂点击目标行 `bounds` 中心点，进入聊天详情。

进入后必须重新截图并匹配 `screens/screen_聊天界面.jpg`：

- 如果不在聊天界面，尝试重新点击目标或结束本轮。
- 如果已经在聊天界面，按上一步判断是否需要 `dialogue` OCR。

需要读取聊天详情时，使用 `dialogue` 模式：

1. 识别聊天区域。
2. 从 `dialogues` 中找到 `sender1` 发出的最后一条非空消息。
3. 该消息作为本轮发给 AI 的用户输入。
4. `name` 仍使用列表页选中行的 `name`，用于聊天记忆，不被聊天标题 OCR 覆盖，除非列表页为空。

如果列表内容已经足够直接回复，则跳过 `dialogue` OCR，直接进入输入和发送流程。

## 10. 输入框、麦克风和 TTS

在聊天界面中先匹配 `buttons/btn_输入框.jpg`。

点击规则：

```text
x = match_center_x - 0.5
y = match_center_y
```

该点击用于让输入框或语音输入面板弹出。点击后重新截图并匹配 `buttons/btn_麦克风按钮.jpg`。

麦克风流程：

1. 匹配麦克风按钮。
2. 点击麦克风。
3. 调用 TTS 或机械臂语音接口，把要输入的回复文本通过扬声器播放出来。
4. 播放完成后固定等待 3 秒。

如果麦克风按钮未出现，按 `step_timeout` 重试；超时后抛出异常进入恢复流程。

## 11. 发送确认

TTS 播放并等待 3 秒后，截图并匹配 `buttons/btn_发送按钮.jpg`。

发送流程：

1. 如果匹配到发送按钮，点击一次。
2. 点击后重新截图。
3. 如果发送按钮还存在，继续点击，直到发送按钮消失或达到超时。
4. 如果发送按钮没有出现，判断是否已经发送完成；无法判断时抛出异常。

这个重复确认用于防止第一次点击没有生效，或输入法状态导致发送按钮仍停留。

## 12. 返回聊天列表

发送完成后进入返回流程：

1. 截图并确认发送按钮是否还存在。
2. 如果仍有 `buttons/btn_发送按钮.jpg`，继续点击发送。
3. 如果没有发送按钮，匹配 `buttons/btn_返回按钮.jpg` 和 `buttons/btn_返回按钮_2.jpg`。
4. 成功匹配返回按钮后连续点击两次。
5. 每次点击后可以短暂等待并重新截图，避免页面动画导致第二次点击落空。
6. 返回两次后应处于 `screens/screen_聊天列表.jpg`。
7. 如果仍不在聊天列表，执行一次兜底返回或结束本轮并记录错误截图。

返回两次是心遇见流程的默认恢复动作，用于从聊天详情或输入面板状态稳定回到消息列表。

## 13. 单轮推荐流程

`XinyuApp.run_once()` 后续应按以下顺序编排：

1. 处理弹窗。
2. 确认当前界面；如果在聊天界面，先返回聊天列表。
3. 在聊天列表检查 `btn_未读消息按钮` 区域是否有红色；无红色则点击一次。
4. 对整个界面执行 `list` OCR。
5. 从 `message_list` 中选择 `unread_count >= 1` 且 `favorability` 最大的目标。
6. 判断列表 `content` 是否可直接作为对话内容；如果是“你好”，从 `runtime/greetings/pingtai.txt` 抽取平台招呼语。
7. 点击目标 `bounds` 中心进入聊天界面。
8. 确认进入 `screen_聊天界面.jpg`。
9. 如果需要详情内容，执行 `dialogue` OCR，读取 `sender1` 最后一条消息。
10. 请求 AI 或使用平台招呼语。
11. 匹配输入框并点击 `x - 0.5` 的位置。
12. 匹配麦克风按钮，点击后播放 TTS。
13. 等待 3 秒。
14. 匹配发送按钮并点击，直到发送按钮消失。
15. 匹配返回按钮，返回两次。
16. 确认回到聊天列表，标记本轮成功。

## 14. 异常和恢复

以下情况本轮直接结束，不算严重错误：

- 未找到未读目标。
- 无法确认聊天列表，但也没有进入明确错误状态。
- 未读入口没有红色，点击后仍没有可处理目标。

以下情况应抛出异常并进入 `BaseApp.on_error()`：

- 已进入聊天界面但无法定位输入框。
- 无法定位麦克风按钮。
- TTS 播放或语音输入接口失败。
- 发送按钮长期存在且无法消失。
- 发送后无法返回聊天列表。

错误处理仍沿用基础流程：记录错误、保存错误截图、尝试机械臂恢复，连续失败达到 `circuit_breaker_threshold` 后打开熔断。

## 15. 状态和日志建议

建议为心遇见补充以下运行状态，便于 UI 和日志排查：

- `popup_check`：检查并关闭弹窗。
- `confirm_xinyu_list`：确认心遇见聊天列表。
- `return_from_chat`：从聊天界面返回列表。
- `unread_button_check`：检查未读按钮红色状态。
- `list_ocr_scan`：列表 OCR 扫描。
- `target_selected`：选中本轮目标。
- `direct_content_reply`：使用列表内容直接回复。
- `greeting_reply_pick`：从 `runtime/greetings/pingtai.txt` 抽取招呼语。
- `enter_chat`：进入聊天界面。
- `dialogue_ocr_read`：聊天详情 OCR。
- `input_box_click`：点击输入框偏移位置。
- `microphone_click`：点击麦克风。
- `tts_playback`：播放 TTS。
- `send_button_click`：点击发送按钮。
- `return_to_list`：返回聊天列表。

关键日志建议输出：

- 目标 `name`、`favorability`、`unread_count`、`content`。
- 是否走列表直回，还是进入聊天详情 OCR。
- AI 输入文本和最终回复文本。
- 发送按钮点击次数。
- 返回后最终界面判断结果。

## 16. 后续开发注意事项

- 心遇见的 `list` OCR 不应复用微信“右侧数字就是未读数”的假设。
- 修改 `message_list` 输出结构时，同步更新 `apps/xinyu/steps.py`、`apps/xinyu/app.py` 和对应测试。
- 新增按钮模板时，优先放入当前 App 的模板目录，不影响微信和环游。
- 任何新增截图步骤都应走弹窗处理后的截图，不要跳过 `capture_after_popups()`。
- `runtime/greetings/pingtai.txt` 不存在或为空时，应回退到 AI 普通回复，而不是让本轮失败。
- 发送后必须确认发送按钮消失，再返回列表。

## 17. 推荐测试范围

修改心遇见流程后至少运行：

```powershell
pytest tests/test_app_ocr_config.py tests/test_ocr_list_rules.py -q
```

如果修改 `apps/xinyu/app.py` 或 `apps/xinyu/steps.py`，建议新增并运行心遇见流程测试，例如：

```powershell
pytest tests/test_visual_asset_contract.py tests/test_runtime_cancellation.py -q
```

提交前建议运行：

```powershell
pytest -q
```
